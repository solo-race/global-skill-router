# Discovery Selection

Ordinary source scouting is the default. Skip extra scouting when supplied current
source evidence is already sufficient. Exact-file tasks, narrow defects and document
or configuration checks use ordinary inspection directly.

Choose the existing `codebase-memory-scout` identity only when relevant files/symbols
are unknown, cross-file relationships materially guide the task, and a suitable graph
project has adequate coverage. Its explicit identity and routing remain owner-controlled;
a generic scout is not a silent replacement for an explicitly selected graph identity.

Do not duplicate broad discovery with ordinary and graph scouts over the same ground.
Normally use 3-4 bounded graph queries, count metadata checks separately, limit results
and trace depth, and return references/graph-evidence-packet.md. Verify current source
before implementation or consequential impact conclusions. Graph evidence never proves
absence, exhaustive impact, dead code, readiness or model identity.

Ambiguous project, stale/partial coverage, unsupported files or unavailable tools ->
report the gap, then source inspection through the already authorized binding when
feasible. Any changed role/identity/model or additional metered assignment requires
its applicable selection and approval. Never rebuild an index or launch an extra
agent merely to make a graph precheck pass. A tool allowlist alone does not prove the
complete effective tool surface.
